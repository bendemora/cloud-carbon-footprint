# Primary publishers of grid intensity data: survey

| | |
|---|---|
| Date | Survey run on 2026-11-06; recorded here on 2026-11-12 |
| Question | For each of the 48 grid zones in the grid zone registry, is there a free source of historical grid carbon intensity, or of generation by fuel that can be converted, at hourly resolution, that a program can read, under a licence that allows commercial use and redistribution? |
| Scope | A desk survey. No source was built and no publisher's API was called |
| Feeds | Design section 5.1 (the catalogue), Phase 2, and the verification backlog in section 14 of `docs/design/2026-11-localised-time-resolved-carbon-estimation.md` |
| Decision it supports | `.adr/0026-grid_intensity_from_primary_publishers.md` |

How to read this: this is a list of leads, not of verified facts. Section 2 says what the evidence is and where it is thin. Section 6 lists the claims that rest on the weakest evidence. Before a source is built, its licence and its endpoint have to be read on the publisher's own pages and recorded as a dated licence declaration in code, as the NESO spike did for NESO. Nothing here is legal advice.

## 1. Answers in brief

1. Yes, for 19 of the 48 zones: Great Britain, France, Germany, Belgium, Finland, two Norwegian zones, one Swedish zone, the eight United States zones, central-southern Brazil, New Zealand and Taiwan. Each has a free publisher of hourly or finer data whose licence, as found, allows commercial use (section 3, class 1).
2. For 16 more zones free hourly data exists, but the licence is unresolved or refuses commercial use (class 2). Five of them, IE, NL, ES, IT-NO and PL, turn on one question: whether ENTSO-E's "Actual Generation per Production Type" data is on ENTSO-E's list of data that may be re-used freely (section 5, point 1).
3. India's three zones have daily data only (class 3). For ten zones no free hourly source that a program can read was found (class 4): MX, SG, ZA, HK, CN, ID, TH, IL, AE and BH. Those stay on the static annual factors.
4. The publishers do not agree on what they publish. Some give intensity, some only a generation mix; some count imports and some do not; some use direct combustion factors and some lifecycle factors (section 5, point 4). Provenance has to carry the basis and the factor type of every value, as the design already requires.
5. Sources that only publish a mix need the project's own table of factors per fuel (design section 5.3), and three of them (NZ, TW, PL) publish per plant or per unit, so they also need a table of which plant burns what.

## 2. How this was checked, and its limits

- Four sweeps (Europe, North America, the rest of the world, and sources that cover several regions) each listed candidate sources. A second pass then tried to confirm or correct each source's licence and access claims, and a last pass reconciled the four lists. Eleven further searches on 2026-11-06 filled gaps for NZ, TW, SG, KR, JP, AU, ENTSO-E and Brazil (section 8).
- **Most publishers' own websites could not be opened** from the session that ran the survey: its network policy refused them. The evidence is therefore web search results that summarise those pages, public GitHub repositories, package metadata on PyPI, the AWS Open Data Registry, and anonymous reads of public cloud storage (the three S3 buckets and the one Google Cloud Storage bucket that section 7 cites). Section 7 marks each entry "confirmed", "corrected by the verifier", "not verified" or "refuted" by the second pass, or says that the second pass or the reconciliation added it. "Not verified" means the publisher's page was not re-read, not that the claim is wrong. 62 of the 105 entries are marked that way.
- The sweep of Asia-Pacific, the Middle East, Africa and Latin America ran out of its search allowance. Its entries rest mainly on the endpoints named in the open `electricitymaps-contrib` parser repository (read at commit `2faa955a`), which shows that an endpoint exists and what it returns but says nothing about the publisher's licence. That repository is AGPL-3.0; it was read for pointers only and no code was taken from it. Zones in that part of the world marked "none found" may have a source that was not looked for.
- History start dates, resolutions and endpoint paths are as the search results or third-party code gave them. Where the NESO spike has since checked a point against the live API, this file uses the spike's value and says so.

That is 19, 16, 3 and 10 zones, 48 in all. For BE, FI, NZ and TW the depth of the history was not confirmed, so their place in class 1 assumes the 12 months. ## 5. Findings that cut across zones

1. **The ENTSO-E licence decides five zones.** ENTSO-E's terms of use have a list of data that may be re-used freely, and CC BY 4.0 was added to that list on 2022-02-18. The survey could not confirm that item 16.1.B&C, actual generation per production type (document type A75), is on the current list, and one open project's data inventory (PyPSA-Eur) records the licence of the Transparency Platform as unknown. If A75 is on the list, IE, NL, ES, IT-NO and PL move to class 1 and CH gains a usable, if inaccurate, feed. IE matters most, because AWS `eu-west-1` is on it. The address that settles it, and that also issues API tokens, is transparency@entsoe.eu. One sweep recorded, from third-party guides, that a token is asked for by email with the subject "Restful API access" after registering on the platform, that a person approves it, and that this takes about three working days. Its record gives 14 addresses as evidence for the whole entry (the first ENTSO-E row of section 7 shows three of them) and does not say which one the lead time came from. Two of the 14 look like third-party guides to the API, going by their addresses alone: <https://progrunners.com/entso-e-api/> and <https://www.fibric.io/integrations/c/sg-entsoe-transparency>. Neither was opened to check, so the lead time is not verified. This is design backlog item 2.
2. **For several European zones the operator's own data has a clearer licence than ENTSO-E's copy of it.** RTE, Elia, Fingrid, SMARD and Elhub each publish under CC BY 4.0 or an equivalent, and three of them publish intensity directly, so no factor table is needed. Where both exist, the operator is the primary publisher in the sense of ADR 0026 and ENTSO-E is the fallback.
3. **Some services have gone.** gridcarbon shut down on 2026-09-13 and leaves a frozen archive. Open Power System Data stopped in 2020. The free CO2 Signal API is no longer a free route.
4. **Bases differ and must not be blended without a label.** NESO divides the CO2 of generation and imports by national demand, with direct combustion factors (NESO spike, section 7.4). RTE's figure is production only, with direct factors. Fingrid and Elia publish a production and a consumption figure. EIA publishes intensity for generated and for consumed electricity. Open Grid Emissions gives consumed rates from combustion only. Ember and Our World in Data use lifecycle factors. A value the project derives from a mix has whatever basis its own factor table has.
5. **Some figures answer a different question.** WattTime's free plan gives a marginal signal for one California region. Climate TRACE publishes a modelled build-margin rate. NREL Cambium models future years. None can stand in for the average intensity of a past hour.
6. **Aggregators.** The free tier and the data portal of Electricity Maps do not allow commercial use without a subscription; ADR 0026 records the decision not to use it.

## 6. Claims that rest on weak evidence

From the reconciliation pass, word for word apart from formatting. Each is a reason not to rely on a line of sections 3 or 7 until the publisher's own page has been read. Where a claim says the design document labels NESO production-based, that label has since been corrected by the NESO spike (`docs/design/spikes/2026-11-neso.md`).

- ENTSO-E A75 commercial_use and redistribution: the global sweep's 'yes' is unsupported. No document quoting the clause 2.5 list shows 16.1.B&C on it, and PyPSA-Eur records the ENTSO-E Transparency licence as 'unknown'. Treat both as unclear.
- gridcarbon Zenodo snapshot commercial_use 'yes' (global sweep): its own DATA-LICENSE.md says upstream terms win where they are stricter, so the European values inherit the unresolved ENTSO-E question. Treat as unclear. GB values come from NESO under CC BY 4.0.
- Elexon BMRS (FUELHH, FUELINST): the open BMRS Data Licence conflicts with Elexon's site-wide copyright page, which prohibits commercial use, and no verifier re-read either. Commercial 'yes' needs written confirmation from Elexon.
- NESO Data Portal historic generation mix: no one read the commercial clause of the NESO Open Data Licence. Third parties label the same data ODC-By or CC BY 4.0, and PyPSA-Eur labels NESO data 'NESO Open Data License v1.0'. Commercial 'yes' is a third-party reading.
- Elia ods192, ods191 and ods201: the CC BY 4.0 claim rests on Elia's general licence page. The per-dataset licence, the resolution (hourly or 15-minute) and the start date are unverified, and one report mentions a CC BY-NC Elia dataset.
- Fingrid and SMARD commercial use is inferred from CC BY 4.0, not stated by the operators, and no verifier could re-check either host.
- eSett CC0 rests on a homepage snapshot about 4.5 years old; check the live site before relying on it.
- Energy-Charts: coverage of zones other than DE and CH, history depth and the /co2eq method are all unverified. Non-German per-type data is probably derived from ENTSO-E, so the CC BY 4.0 default may not settle the licence (inferred).
- RTE eCO2mix: the Licence Ouverte 2.0 text allows commercial reuse, but no one re-read on ODRE that the eco2mix datasets carry that licence.
- OGE: 'hourly 2019 to 2025' is wrong for the public S3 release, where the 2025 hourly per-BA folders are empty. The CC BY 4.0 data licence rests on Zenodo search summaries, the repository states no data licence, and older Zenodo records say MIT.
- EIA-930 hourly CO2: the north_america sweep's 'six-month BALANCE CSVs' route is wrong per PUDL's documentation; the data sits in per-BA spreadsheets from 2018-07-01. EIA's public-domain policy and its API terms of service were cited, but no verifier re-read them.
- EPA CAMPD public domain: the evidence is the EPA ScienceHub licence page and a metadata specification, not a reuse statement specific to CAMPD.
- ERCOT: commercial and redistribution stay 'unclear'. The only new evidence is a third party (Kardashev Labs) reading ERCOT's website terms as permitting use, reproduction and redistribution of publicly available contents.
- CAISO Today's Outlook: no one confirmed that CAISO's API terms bar benchmarking or competitive uses, or that such terms cover the Outlook CSV files.
- PJM Data Miner 2 'no' and AESO 'no' rest on quoted terms that no verifier could re-read. They are consistent with Kardashev Labs excluding PJM Data Miner fields from its open release.
- IESO: the commercial scope of its limited licence is unclear, because the quoted terms do not mention commercial use.
- Hydro-Quebec: redistribution 'no' is stricter than CC BY-NC 4.0, which allows non-commercial redistribution. For this project's commercial outputs the practical answer is still no.
- OpenElectricity: the APAC sweep's commercial 'unclear' is now 'no' on every free plan (verified in its backend code). The licence of the token-free static JSON files is still unverified.
- PSE (PL): commercial reuse rests on a third party's reading of PSE's BIP conditions, which are written for www.pse.pl, not for the API.
- ONS (BR-CS): CC-BY 4.0 comes from the AWS Open Data Registry entry. The ONS portal's own licence page was not read, and mapping subsystem SE/CO to BR-CS is inferred.
- Ember: OWID's ingestion metadata confirms CC BY 4.0. That the API key is free comes only from third parties, and the India subnational file carries no licence text.
- Carbon Monitor-Power: only the paper's CC BY 4.0 was seen; the dataset's own licence text was never read.
- IEA Real-Time Electricity Tracker: the licence (CC BY 4.0 or not) and whether free programmatic access exists are still contradictory.
- Electricity Maps: the ODbL label on portal pages conflicts with Terms of Service that require payment for any commercial use. Treat it as not free for this project.
- NESO Carbon Intensity API basis: the design doc's 'production-based' label conflicts with the methodology PDF, which includes imports and divides by national demand.
- Japanese TSO CSVs, KPX, GSO, CEN, Grid-India, CEA/NPP, Eskom, Noga and Transpower: every licence is unverified, and several are website endpoints rather than documented APIs.
- Climate TRACE MBERs: the AWS registry confirms 'no license restrictions', but the values are a modelled build-margin rate. A zone it 'covers' is not covered for average-intensity estimation.

## 8. Further searches on 2026-11-06

Made after the sweeps, to fill the gaps the reconciliation pass named. Each is a web search result, not a reading of the page itself.

- New Zealand: EMI's legal information page licenses the site's material under CC BY 4.0 unless a dataset says otherwise (<https://www.emi.ea.govt.nz/LegalInformation/>). The dataset is generation output by plant, by half-hourly trading period (<https://www.emi.ea.govt.nz/Wholesale/Datasets/Generation/Generation_MD>). One third party reports a plain copyright notice on the dataset instead, so the dataset's own page has to be read.
- Taiwan: dataset 37331 gives each Taipower unit's net generation every 10 minutes under the Open Government Data License 1.0 (<https://data.gov.tw/en/datasets/37331>). The licence text grants a royalty-free, perpetual licence and names CC BY 4.0 as compatible (<https://data.gov.tw/license>, <https://spdx.org/licenses/OGDL-Taiwan-1.0.html>).
- Korea: data.go.kr lists a KPX service for generation by source with a five-minute endpoint (<https://www.data.go.kr/en/data/15158491/openapi.do>). Its licence type was not in the results.
- Japan: a third-party project records the formats of the operators' area files and that TEPCO's page answers HTTP 403 outside Japan (<https://github.com/open-energy-transition/demandcast/issues/338>). No terms of use were found.
- Australia: AEMO publishes under its own copyright permissions notice, which a package author describes as similar to CC BY 4.0 but not the same (<https://cran.r-project.org/web/packages/aemo/index.html>). One archive readme says its data is not intended for commercial use (<https://www.nemweb.com.au/Data_Archive/Wholesale_Electricity/NEMDE/2021/NEMDE_2021_01/NEMDE_Market_Data/NEMDE_Files/Readme.htm>).
- Singapore: EMA publishes half-hourly system demand, not generation by fuel (<https://www.ema.gov.sg/resources/statistics/half-hourly-system-demand-data>), and an annual fuel mix (<https://data.gov.sg/datasets/d_dec34f3ed7daeb6429c8d8b7c36852d2/view>).
- ENTSO-E: the legal terms page describes the list of freely re-usable data and its 2022 change (<https://transparencyplatform.zendesk.com/hc/en-us/articles/40921911218961-Legal-Terms-and-Conditions>); a 2019 notice says the operators agreed to release data under an open licence (<https://www.entsoe.eu/news/2019/02/01/tsos-increase-number-of-open-data-available-through-entso-e-s-transparency-platform/>). No result showed whether item 16.1.B&C is on the current list.
- Brazil: the AWS Open Data Registry entry for the ONS portal gives CC BY 4.0 (<https://registry.opendata.aws/ons-opendata-portal/>). That the hourly generation dataset carries it was not confirmed.

## 9. What this means for the plan

These are recommendations for the project owner. None of them changes the phase plan by itself.

1. Phase 2's three sources stand: NESO, EIA and ENTSO-E. NESO is specified by its spike. EIA needs a free API key. ENTSO-E needs a token and the answer to the licence question in section 5, point 1, and should declare a licence that needs acknowledgement until that answer is in writing.
2. For FR, DE, BE, FI and NO, build on the operator's own data when a source for the zone is built, and keep ENTSO-E as the fallback. Each needs a short spike of its own first: licence and endpoint read on the publisher's pages, fixtures recorded.
3. The per-fuel factor table of design section 5.3 is needed by every mix-only publisher, so it is worth building once, with the EIA source.
4. BR-CS, NZ and TW are open by the evidence found and come after the sources above. NZ and TW need a plant-to-fuel table as well.
5. Class 2 zones wait for a licence answer or a written permission (IESO, AESO, Hydro-Québec, AEMO, the Japanese operators, KPX). Asking costs an email each.
6. The grid zone registry has to be checked before the EIA source is built: the survey looked for publishers of the zones as the registry names them, and at least one United States mapping looks wrong (design section 5.5).
