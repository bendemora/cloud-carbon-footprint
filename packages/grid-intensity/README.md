# @cloud-carbon-footprint/grid-intensity

Grid carbon intensity source layer for Cloud Carbon Footprint. It replaces the single static grid emissions factor per region with pluggable sources that report what they can deliver per zone (granularity, lookback, accounting basis, licence), a resolver that picks the best source for each usage period, and provenance on every estimate.

Design: `docs/design/2026-11-localised-time-resolved-carbon-estimation.md`, section 6. Decision record: `.adr/0022-grid_intensity_source_layer.md`.

## Status

Phase 1. This package contains:

- The interfaces from section 6.1 of the design (`GridIntensitySource`, `IntensityStore`, `IntensityResolver`, `IntensityPoint`, `Provenance`, licence and capability types).
- `StaticSource`: the CCF static annual factors as a source. Always available, quality tier D. The factor tables stay in the provider packages and are given to the constructor, so this package depends on no provider package.
- `GridIntensityResolver`: the resolution policy from section 6.2. Sources are tried in configured order; those that cannot deliver data at least as fine as the usage period are tried only after the others, finest first. Commercial, non-commercial and custom licences need an operator acknowledgement. Stored points are read first and only missing periods are fetched. Failures are logged once per source and zone, negative-cached for the capability TTL, and never abort a run.
- Stores (section 6.6): `LocalIntensityStore` (one JSON file per source, zone, granularity and month under `GRID_INTENSITY_STORE_PATH`), `MongoDbIntensityStore` (collection `grid-intensity-points` in the `ccf` database, using `MONGODB_URI`), and `InMemoryIntensityStore`. The static source is never stored. Store files may hold licensed data: `.ccf/` is in `.gitignore`.
  - `LocalIntensityStore` writes one file at a time within a process, through a temporary file and a rename, so overlapping writes keep every point and no file is left half-written. Two processes on one directory are not coordinated: the later write of a month file wins, and the other process's points are fetched again when needed. Ids that differ only in case (one directory on macOS) are never mixed: their writes are serialised, and the second id's write fails with an error naming both. `purge` skips files the store did not write, removes temporary files older than both the cut-off and an hour, and reports a file it cannot read after purging the rest.
  - `MongoDbIntensityStore` remembers a failed connection for five minutes, then tries again, so a long-running API server recovers when MongoDB is back.
- `resolveEmissionsFactors`: the adapter the provider packages will call in place of `getEmissionsFactors`. It builds a default resolver and store from the configuration below. When the static source is used, it returns the caller's table unchanged, so estimates stay identical to today's. `shutdownDefaultResolver()` closes the store at the end of a run.
- `deriveQualityTier` (section 6.4), `requiresAcknowledgement` (section 6.3), UTC period helpers, time-weighting and tCO2e/gCO2e conversions.

The AWS, GCP and Azure billing-data paths (Cost and Usage Reports, the billing export, Consumption Management) and their recommendations call `resolveEmissionsFactors` in place of `getEmissionsFactors`, for known and unknown usage alike. The billing-data paths attach the provenance to each `ServiceData` row (`provenance`, including `gCO2ePerKWh`, the intensity applied). With the default configuration every row resolves to the static factors, so estimates are unchanged. Estimates from the cloud usage APIs (billing data turned off), ALI and on-premise rows carry no provenance yet.

While `ELECTRICITY_MAPS_TOKEN` is set, the adapter keeps using the existing Electricity Maps v3 lookup in `packages/common` (one hourly sample at the start of each period), labelled `electricitymaps-v3`, until the v4 source replaces it. A failed v3 request (network error, a body that is not JSON, an HTTP 401 saying the token is invalid, or HTTP 5xx) throws an `ElectricityMapsRequestError` and stops the billing-data run, as a failed request did before this package; Azure, which skips a subscription on other errors, lets this one through. Falling back would repeat the failing request for every billing row, and the estimates cache would keep the fallback rows for good, because a cached day is never estimated again. A v3 answer without a value (for example the HTTP 401 for a zone or endpoint the token has no access to) falls back to the configured sources for that row.

Not yet here: the Electricity Maps v4 source, the doctor command and the capabilities endpoint.

## Configuration

| Key                                       | Default               | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GRID_INTENSITY_SOURCES`                  | `static`              | Comma-separated source ids in priority order. Only `static` exists so far; unknown ids are ignored with a warning.                                                                                                                                                                                                                                                                                                                                                                                    |
| `GRID_INTENSITY_LICENCE_ACKNOWLEDGEMENTS` | empty                 | Source ids the operator asserts they are licensed to use. Required for sources with a commercial, non-commercial or custom licence.                                                                                                                                                                                                                                                                                                                                                                   |
| `GRID_INTENSITY_CAPABILITY_TTL_HOURS`     | `24`                  | How long capability answers and failures are cached.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `GRID_INTENSITY_STORE`                    | `LOCAL`               | Where fetched points are kept: `LOCAL` (JSON files) or `MONGODB` (uses `MONGODB_URI` and `MONGODB_CREDENTIALS`). If `MONGODB_URI` is missing or malformed, the `MONGODB_CREDENTIALS` file cannot be read, or the mode is unknown, points are kept in memory for the run, with a warning. A MongoDB server that cannot be reached or rejects the credentials is logged as a store failure, and points are not kept until a connection succeeds; the store tries again five minutes after each failure. |
| `GRID_INTENSITY_STORE_PATH`               | `.ccf/grid-intensity` | Directory of the `LOCAL` store.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

## Units

Sources publish gCO2e/kWh; the CCF estimators use tCO2e/kWh. `tonnesToGrams` and `gramsToTonnes` round to 12 significant figures so that a static table value converted to grams and back is the identical number (the tables carry at most 10 significant figures).

## Static zones

`StaticSource` names zones `<provider>:<region>` with the provider in lower case, for example `aws:eu-west-2`. A region missing from a table, or whose factor is 0, maps to `<provider>:Unknown` when the table has an `Unknown` entry. That matches `estimateCo2` in `packages/core`, which applies `factors[region] || factors.Unknown`, so provenance reports the factor actually applied. GCP's carbon-free-energy table has a 0 for `europe-north2` because Google reports the region as fully carbon-free; `estimateCo2` treats that 0 as missing and applies the table's Unknown average (188.94 gCO2e/kWh), an upstream overestimate that this package does not change. The 0 to 1500 gCO2e/kWh bounds apply to fetched points only, not to the static tables, whose GCP multi-region factors are sums across data centres (up to 3810 for `us`).

The basis and factor type of each table default to `location-production` and `direct`, and the AWS, GCP and Azure wiring uses these defaults for every table, including GCP's carbon-free-energy one. The default is an inference from the sources the CCF methodology cites (EPA eGRID, EEA and carbonfootprint.com are generation-based), not a verified label; the GCP tables need checking against Google's published method (design section 14, item 9).
