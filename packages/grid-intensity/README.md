# @cloud-carbon-footprint/grid-intensity

Grid carbon intensity source layer for Cloud Carbon Footprint. It replaces the single static grid emissions factor per region with pluggable sources that report what they can deliver per zone (granularity, lookback, accounting basis, licence), a resolver that picks the best source for each usage period, and provenance on every estimate.

Design: `docs/design/2026-11-localised-time-resolved-carbon-estimation.md`, section 6. Decision records: `.adr/0022-grid_intensity_source_layer.md` and `.adr/0026-grid_intensity_from_primary_publishers.md`.

## Status

Phase 1 is complete; the open sources of Phase 2 come next. This package contains:

- The interfaces from section 6.1 of the design (`GridIntensitySource`, `IntensityStore`, `IntensityResolver`, `IntensityPoint`, `Provenance`, licence and capability types).
- `StaticSource`: the CCF static annual factors as a source. Always available, quality tier D. The factor tables stay in the provider packages and are given to the constructor, so this package depends on no provider package.
- `GridIntensityResolver`: the resolution policy from section 6.2. Sources are tried in configured order; those whose data is coarser than the usage period (monthly data for a week, annual data for a quarter) are tried only after the others, finest first. Commercial, non-commercial and custom licences need an operator acknowledgement. Stored points are read first, whatever the source's lookback window or recent failures (also when a fresh process's first capability probe fails), and only missing periods inside the window are fetched. A source that covers only part of the period is kept as a fallback while later sources are tried: the first that covers the whole period wins, unless it is the static source and live data covers part of it. A day that runs past the end of a source's data (today) is served from its finest data up to that point and marked estimated. Points that are not whole UTC periods of the requested granularity and zone are dropped with a warning. A failure stops the zone's fetches for the capability TTL and never aborts a run. Each warning is logged at most once per source, zone and kind per TTL, and a store warning is logged again once the store has worked in between. Points from sources with `session` retention are kept in memory, never in the store, and released by the first resolve call after the TTL.
- Stores (section 6.6): `LocalIntensityStore` (one JSON file per source, zone, granularity and month under `GRID_INTENSITY_STORE_PATH`), `MongoDbIntensityStore` (collection `grid-intensity-points` in the `ccf` database, using `MONGODB_URI`), and `InMemoryIntensityStore`. The static source is never stored. Store files may hold licensed data: `.ccf/` is in `.gitignore`.
  - `LocalIntensityStore` writes one file at a time within a process, through a temporary file and a rename, so overlapping writes keep every point and no file is left half-written. Two processes on one directory are not coordinated: the later write of a month file wins, and the other process's points are fetched again when needed. Ids that differ only in case (one directory on macOS) are never mixed: their writes are serialised, and the second id's write fails with an error naming both. `purge` skips files the store did not write, removes temporary files older than both the cut-off and an hour, and reports a file it cannot read after purging the rest.
  - `MongoDbIntensityStore` remembers a failed connection for five minutes, then tries again, so a long-running API server recovers when MongoDB is back.
- The grid zone registry (section 5.5): `GRID_ZONES` maps AWS, GCP and Azure regions to the electricity grid each is on (`GB`, `US-MIDA-PJM`), or to null where it is not known, and `gridZoneOf(provider, region)` looks one up. A source maps a region to its own zone in two steps: region to grid zone in the registry, then grid zone to the source's zone in a table the source holds. `GRID_ZONE_REGISTRY_VERSION` is to be raised whenever a mapping changes; a test fails when the registry no longer matches the fingerprint recorded for its version.
- `resolveEmissionsFactors`: the adapter that AWS, GCP and Azure call for the grid emissions factor of a region and period. It builds a default resolver and store from the configuration below. When the static source is used, it returns the caller's table unchanged, so those estimates are the ones the static factors have always given. `shutdownDefaultResolver()` closes the store at the end of a run.
- `deriveQualityTier` (section 6.4), `requiresAcknowledgement` (section 6.3), UTC period helpers, time-weighting and tCO2e/gCO2e conversions.
- `GridIntensityCapabilityReporter` (section 6.5): the report behind the doctor command and the capabilities endpoint, described under "The doctor" below. It reads what a resolver knows about its sources through `GridIntensityResolver.sourceViews` (each source's zone for a region, the capability answer the resolver holds, whether the licence is acknowledged, the probe answer, kept for the capability TTL, and the reason a zone's fetches are stopped). `createCapabilityReporter` builds it on the default resolver from the configuration, with the provider regions and static tables the app layer gives it.

The AWS, GCP and Azure billing-data paths (Cost and Usage Reports, the billing export, Consumption Management) and their recommendations call `resolveEmissionsFactors`, for known and unknown usage alike. The billing-data paths attach the provenance to each `ServiceData` row (`provenance`, including `gCO2ePerKWh`, the intensity applied). With the default configuration every row resolves to the static factors, so estimates are unchanged. Estimates from the cloud usage APIs (billing data turned off), ALI and on-premise rows carry no provenance yet.

Live sources in this package read a primary publisher of grid data: a system operator, a market operator or a public agency. Electricity Maps is not called or built in: ADR 0026 removed the lookup upstream CCF has and cancelled the planned source. `ELECTRICITY_MAPS_TOKEN` is ignored, and a warning is logged while it is set, when the default resolver is built. The ADR also records the one indirect use that remains: the Google Cloud static factors are Google's published figures, which Google derives from Electricity Maps data.

Not yet here: any source other than the static factors. The NESO source for Great Britain is the first.

## The doctor

`yarn workspace @cloud-carbon-footprint/cli grid-intensity-doctor` prints the capability report as a table, and `GET /api/grid-intensity/capabilities` returns the same report as JSON. Neither needs cloud credentials, and neither calls a data endpoint of any source.

The report gives the grid zone of every region in the region tables of AWS, Google Cloud and Azure, the providers whose estimates use this package (`packages/app` builds the list; a provider with `<PROVIDER>_INCLUDE_ESTIMATES=false` is left out), with one entry per configured source. Each entry gives:

- The source's own zone for the region, or none.
- The licence state: `open` (no acknowledgement needed), `acknowledged` or `needs-acknowledgement` (whether the source is listed in `GRID_INTENSITY_LICENCE_ACKNOWLEDGEMENTS`; a source that needs acknowledgement is not used), or `unavailable` (the source has no zone, or no data, for the region).
- The best quality tier the source can deliver in the last 24 hours, the last 30 days and the last 12 months, each ending now. Tiers are for a day of usage, the finest usage period CCF produces, so hourly data shows as tier B; tier A needs hourly usage (design section 7). The tier is what the source offers, also for a source that needs acknowledgement.
- The share of the UTC days in each window that the source can serve, in whole or in part. The table shows it as a percentage when it is below 100, so a source with a three-month lookback shows about 25 % for the last 12 months, and one whose data arrives two days late shows no tier for the last 24 hours.
- The attribution text of the source's licence, and any error: a probe of the source that failed or was not authenticated, or the reason the resolver has stopped the zone's fetches.

With the default configuration every region shows the `static` source at tier D in all three windows.

What the report is based on: tiers and shares are derived from each zone's capability (granularities and lookback window) by the rules the resolver applies to a day of usage, so they describe what a source says it can deliver, not what it has returned. Points already in the store from before a source's lookback window are used by estimates but are not counted. In the API server the report uses the same resolver as the estimates, so it shows the capability answers and failures the server has met; the command starts from nothing each time.

## Units

Sources publish gCO2e/kWh; the CCF estimators use tCO2e/kWh. `tonnesToGrams` and `gramsToTonnes` round to 12 significant figures so that a static table value converted to grams and back is the identical number (the tables carry at most 10 significant figures).

## Static zones

`StaticSource` names zones `<provider>:<region>` with the provider in lower case, for example `aws:eu-west-2`. A region missing from a table, or whose factor is 0, maps to `<provider>:Unknown` when the table has an `Unknown` entry. That matches `estimateCo2` in `packages/core`, which applies `factors[region] || factors.Unknown`, so provenance reports the factor actually applied. GCP's carbon-free-energy table has a 0 for `europe-north2` because Google reports the region as fully carbon-free; `estimateCo2` treats that 0 as missing and applies the table's Unknown average (188.94 gCO2e/kWh), an upstream overestimate that this package does not change. The 0 to 1500 gCO2e/kWh bounds apply to fetched points only, not to the static tables, whose GCP multi-region factors are sums across data centres (up to 3810 for `us`).

The basis and factor type of each table default to `location-production` and `direct`, and the AWS, GCP and Azure wiring uses these defaults for every table, including GCP's carbon-free-energy one. The default is an inference from the sources the CCF methodology cites (EPA eGRID, EEA and carbonfootprint.com are generation-based), not a verified label; the GCP tables need checking against Google's published method (design section 14, item 9).
